研究日期：2026-10-24（Asia/Taipei）  
对象：KINGKAZMAX「創作一個自己的形象」  
证据范围：公开官网、开发者提供的商店说明、官方使用文档、官方模型卡；未登录竞品、未实际付费生成。以下将官方事实与本项目建议分开记录。

### 捏Ta 与 Neta Studio 的界限

用户提到的“捏它”按“捏Ta”产品研究。国内官网为 `nieta.art`。另一个官方产品入口 `neta.art` 当前公开首页展示 Neta Studio 的世界生成、剧情场景、游戏、地图等内容；它不能直接作为捏Ta App 现行角色编辑器布局的证据。当前公开首页能看到一句话输入起点、作品案例与开始创作入口，本研究只将这些作为落地页的信息组织参考，不声称已经实测 App 内的所有操作。[Neta Studio 首页](https://neta.art/)、[官方产品介绍](https://neta.art/legal/about-neta)。

捏Ta 官方公开页面没有在本次查阅内容中提供可直接购买并调用的通用生图 API 接入文档。因此不能把“接入捏Ta模型”写成已经可用的服务承诺。

### 开源模型与在线服务的区别

Neta.art 官方模型卡提供 Neta Lumina：面向动漫图像创作，支持自然语言与多语言，官方示例使用 ComfyUI，并列出至少 8 GB 显存的要求；模型卡显示 Apache 2.0。页面当时显示没有部署该模型的 Hugging Face Inference Provider。开源权重可用于评估自托管方案，但仍需实际推理服务器、部署和负载测试，不等于一条免费、稳定的托管 API。[官方 Neta Lumina 模型卡](https://huggingface.co/neta-art/Neta-Lumina)、[官方发布说明](https://neta.art/blog/neta_lumina)。

NovelAI 的参考能力存在模型版本限制：所查 Precise Reference 文档标注适用于 V4.5，且与 Vibe Transfer 不兼容。不能因某竞品展示某个按钮，推断本项目选择的 API 一定有相同能力。[官方参考文档](https://docs.novelai.net/en/image/precisereference/)。

## 2. 本站现状与具体问题

以下来自本地 `index.html`、`portrait-lab.js` 与上一版交付说明的检查，不是竞品结论。

现有版本已经有描述、风格、可选照片、生成状态、馆藏选择、本地图片、画布微调与 PNG 导出。主要问题是生成表单与全部编辑选项上下连续铺开，用户需要先理解两套机制；手机预览与下方参数距离较长；照片缺少醒目的参考缩略图；生成历史与重用设定不足；服务未连接时没有完整的操作恢复路径。AI 生成结果与原始馆藏都可以编辑，但来源需要始终可见。

## 3. 建议采用的产品结构

以下是结合证据作出的设计建议，并非对竞品 UI 的照搬。

### 首屏：一个工作台，三种起点

主标题保持「Create your own character. / 創作一個自己的形象。」。标题下只说明流程：选择起点 → 描述或挑选角色 → 生成与微调 → 下载。

- **Describe / 文字創作**：自然语言描述、少量可以点入的示例、风格选择。
- **Reference / 參考照片**：显示缩略图、替换与移除、明确“哪些特征想保留”的输入提示。选择照片后再显示照片传输说明，生成前取得明确同意。
- **From collection / 從館藏開始**：沿用统一馆藏，提供可搜索/可辨认的起点，不建立第二套不同编号的角色库。

不需要把三个起点变成复杂向导；采用可立即切换的文字标签，并保留输入。高级参数延后显示。

### 预览与操作的层级

桌面用编辑区与较大的方形预览并排，预览保持可见；屏幕较窄时使用稳定的单列顺序，生成完成后把结果带到视野内。预览下方固定显示当前来源、分辨率、一个主要动作“Download PNG”。生成按钮留在生成表单；下载只作用于当前画布。

微调使用独立标签或折叠区。默认只露出位置、大小、背景；材质、像素化、色相、碎片效果作为展开项。当前选中态应通过文字、底色和边框清楚表达，不能只靠颜色。

风格选择可用三张有名称的样本卡或精简文字卡，底层保留单一真实表单值。样本如果用现有素材演示，应注明它是风格方向示意，不暗示每张示例都是该模型刚生成的结果。

### 成功之后继续创作

保留最近几次成功结果，可重新选回并复用描述与风格。若采用浏览器本地存储，明确“只保存在此浏览器”，提供删除/清空；上传照片默认不持久保存。生成失败、照片损坏、网络断开时保留当前结果与用户输入。

“Use as reference / 用此圖再創作”应真的将结果送入受支持的参考图路径。若尚未实现，使用“Reuse description / 重用描述”更准确。不要用与现有 API 不匹配的“锁定角色”“精确保持五官”等承诺。

## 4. 高级感的可检验标准

“高级”落实为秩序、清晰度和稳定操作，而不是额外添加装饰。

| 方面 | 本次应达到的行为 |
| --- | --- |
| 视觉重心 | 角色预览优先；控件集中于有限列宽；留白由统一间距形成。 |
| 字体 | 沿用全站字体与字号层级，说明文本保持可读；不把主要说明压至极小字号。 |
| 色彩 | 沿用黑白灰和品牌蓝；一个主要动作，次要操作使用文字。 |
| 手机 | 390 px 宽无横向溢出；主要点击区域约 44 px；软键盘出现时不遮住提交或错误。 |
| 可访问性 | 所有字段有可见标签，Tab 可达，明确焦点，状态使用 live region；禁用原因可读。 |
| 等待 | 显示真实阶段或已等待时间，不展示没有后端依据的百分比；阻止重复提交。 |
| 错误 | 区分额度、频率、网络、服务未连接；提供相关恢复动作，保留已有结果。 |
| 导出 | 文件格式、尺寸与透明性说明准确；下载的是当前可见结果。 |

## 5. 模型与后端交付验收

这部分是交付要求，不属于竞品宣传信息。应以真实部署结果判断“已接通”：

1. 公网生产 API 的健康检查返回已就绪，模型配置与实际可调用模型一致。
2. 完成一次真实文字生成、一次真实照片参考生成；记录请求类型、耗时、结果尺寸及结果文件，隐去凭据与个人照片。
3. 在生产页面发起并收到生成结果；失败分支不能被模拟成功图掩盖。
4. 模型凭据仅位于服务端；浏览器只持有公开地址和可公开的验证标识。
5. 公开入口有可验证的防滥用与花费控制；自动重试不得重复触发付费生成。
6. 英文与繁中、桌面与手机均通过生成 → 微调 → 下载链路。
7. GitHub 与 Figma 同步记录必须与本次源码和真实可用状态一致。

如果账户或模型额度阻断生产调用，应给出具体服务响应和剩余步骤。UI 可以完成且发布，但文案应继续明确 AI 服务未就绪，不能把代码接线当作模型已成功上线。

## 6. 本轮建议优先级

**P0：** 三种起点、明确生成/微调分层、大预览、照片缩略图、真实服务状态、生产模型接通与两种输入验收。  
**P1：** 可复用的本地结果历史、描述示例、输入字数提示、移动端操作位置与错误恢复。  
**后续：** 多角度角色设定图、局部重绘、多角色场景、公开社区；这些依赖模型能力与完整的数据/账户设计，不应在本次用空入口占位。
